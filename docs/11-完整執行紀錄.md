## 階段 1：驗證所有手推的公式

```bash
python tests/test_layers.py
```

### 程式碼在做什麼

不用 PyTorch 的 autograd 對答案，而是回到梯度的**定義**直接量：

$$\frac{\partial L}{\partial w} \approx \frac{L(w+\varepsilon) - L(w-\varepsilon)}{2\varepsilon}$$

```python
# scratch/gradcheck.py（節錄）
y0 = layer.forward(x)
dy = torch.randn(y0.shape)          # 隨機的上游梯度
dx = layer.backward(dy)             # 手推公式算出來的

flat[i] = orig + eps; lp = float((layer.forward(x) * dy).sum())
flat[i] = orig - eps; lm = float((layer.forward(x) * dy).sum())
num = (lp - lm) / (2 * eps)         # 有限差分算出來的
rel = abs(num - float(dx.reshape(-1)[i])) / ...
```

人工造一個純量 loss L = Σ(y ⊙ dy)，這樣 ∂L / ∂y 剛好等於 `dy`，
就能用任意的 `dy` 去測 backward 對不對。

用**中央差分**而不是單邊，因為誤差是 O(ε²) 而不是 O(ε)。
整個檢查跑在 `float64` 上，避免 `float32` 的捨入誤差蓋過訊號。

### 實際輸出

```

==================================================================
  Linear 無bias                 最大相對誤差 2.29e-12   PASS
  Linear 有bias                 最大相對誤差 2.03e-12   PASS
```

含開根號、除法、σ(1-σ) 的層（RMSNorm、SwiGLU）在 10⁻⁶ ~ 10⁻⁷，
因為浮點誤差會累積。

## 階段 2：訓練 BPE tokenizer

```bash
python train.py --tokenizer bpe --vocab 6400 ...
```

### 程式碼在做什麼

$$\left\lvert\mathcal{V}\right\rvert = \left\lvert\mathcal{V}_0\right\rvert + M$$

反覆合併最高頻的相鄰配對，每合併一次詞表 +1，到目標大小就停。

```python
# tokenizer/bpe.py（節錄）
for step in range(n_merges):
    pair, cnt = max(pair_cnt.items(), key=lambda kv: kv[1])   # 最高頻的配對
    new_sym = pair[0] + pair[1]
    for i in pair_where[pair]:                                # 只更新受影響的詞塊
        deindex_word(i)
        ...把 pair 換成 new_sym...
        index_word(i)
    tk.merges.append(pair)
    tk.itos.append(new_sym)                                   # 詞表 +1
```

`pair_where` 記錄「哪些詞塊含有這個配對」，合併時只更新受影響的那些，
不用每輪重掃整份語料——否則 1,173 次合併會跑很久。

### 實際輸出

```
詞塊 1,826,987 個（相異 599,629 個），字元 5,415,807 個
起始詞表 5,227（4 特殊 + 5,223 字元）
目標 6,400 → 需要合併 1,173 次

  合併 #1      '可' + '以' -> '可以'  (23,763 次)   詞表 5,228
  合併 #1000   '生' + '產' -> '生產'  (393 次)      詞表 6,227

完成，最終詞表 6,400
```

5,227 + 1,173 = 6,400。**這就是「詞表 6400 哪來的」的答案。**

注意合併次數一路遞減：23,763 → 393。這給了一個實用判斷——
**如果最後幾次合併降到個位數，代表詞表開太大了**。

> 完整的合併紀錄：`traces/bpe_training.txt`（54 行）

## 階段 3：訓練模型

### 模型規格

```
模型結構
==============================================================
  embedding                           1,638,400
  block0                                778,752
  block1                                778,752
  block2                                778,752
  block3                                778,752
  final_norm                                256
  lm_head (與 embedding 共用)                    0
  ----------------------------------------------
  總計                                  4,753,664
  embedding 佔比                            34.5%

optimizer 拿到 38 個參數張量
```

`lm_head` 是 0，因為它跟 embedding 共用同一個張量（weight tying）。
`optimizer 拿到 38 個張量`——**embedding 就在這 38 個裡面**，跟 `q_proj` 平起平坐。

### 訓練迴圈

```python
# train.py（節錄）
model.zero_grad()
logits = model.forward(x, tr)          # 前向
loss   = ce.forward(logits, y, tr)     # 算 loss
dlogits = ce.backward(tr)              # dz = (p − y) / N
model.backward(dlogits, tr)            # 反向，逐層往下

gnorm = opt.clip_grad_norm(args.clip)  # 全域梯度裁剪
opt.step(tr, watch='embed.E')          # 這一行才真的改動權重
```

**注意 `model.backward()` 和 `opt.step()` 是兩件事。**
前者只算出「該往哪修」存進梯度表，後者才動權重。

### 骨架（行號可直接跳）

```
   8  這一批的資料                    ← 這批文字長什麼樣
  19  前向傳播

  45    ===== block0 =====           ← 每個 block 約 100 行

 510  反向傳播
 776    ===== block0 · backward =====
 851    embed · backward（scatter-add）      ← 兩條梯度路徑的拆解

```

`block1` / `block2` / `block3` 的結構跟 `block0` 一模一樣，**看一個就夠**。

### 導覽：五個最值得看的片段

---

**① 第 25 行 — 查表就是查表**

```
公式:  x = E[ids]
       等價於 x = one_hot(ids) @ E，只是跳過了乘以 0 的部分
ids                    shape (64, 128)
x                      shape (64, 128, 256)

      位置       查哪一列                        E[id] 的前 4 維
       t=0        id=4        +0.01647  -0.04764  +0.02504  +0.00472
       t=1     id=5868        -0.00623  +0.02665  -0.00391  -0.01012

>> 這一批用到 2036 個不同的 token，詞表共 6400 個。
>> 剩下 4364 列這一步完全沒被碰到——反向時它們的梯度會是 0。
```

前向沒有任何乘法，就是索引。記住 `2036 / 6400` 這個數字，第 ④ 點會用到。

---

**② 第 493 行 — 整條鏈唯一知道答案的地方**

```
公式:  dz = ( p − y ) / N

    token id             p         y      dz = (p−y)/N          作用
        4656      +0.00048  +0.00000        +5.920e-08         壓下去
         220      +0.00046  +0.00000        +5.575e-08         壓下去
        5868      +0.00026  +1.00000          -0.00012     拉上來（正解）
```

正解那一格 `y = 1`，所以 dz 是**負的**。更新時 E ← E - ηdz，負負得正，分數被推高。
其他格全是正的，分數被壓低。

**這一行就是整個訓練的全部監督訊號。** 往下每一層都只是機械式的微分。

---

**③ 第 851 行 — scatter-add，以及它不是唯一的來源**

```
公式:  dE[v] += Σ_{t : id_t = v}  dx[t]

這一列的梯度其實是兩條路加起來的：
                       來源       dE[5][0]      有幾列非零
    輸入側（本步 scatter-add）      +0.00125     2036 / 6400   ← 稀疏
      輸出側（weight tying）      -0.00420     6400 / 6400   ← 稠密
            合計 dE[5][0]      -0.00295     6400 / 6400
```

`2036 / 6400` 正是第 ① 點那個數字——輸入側只碰得到出現過的 token。
但因為 E 同時是分類器權重，softmax 會碰到**每一列**，所以總梯度是稠密的。

注意兩條路的符號還相反（`+0.00125` vs `-0.00420`），合計後變號。

---

**④ 第 889 行 — 位移恰好等於 lr**

```
更新前 p        +0.00388     +0.04323     -0.00344     +0.01698
梯度   g      -1.290e-06   +8.668e-05   -5.620e-05   -6.518e-06
m̂            -1.290e-06   +8.668e-05   -5.620e-05   -6.518e-06
√v̂           +1.290e-06   +8.668e-05   +5.620e-05   +6.518e-06
m̂/(√v̂+ε)      -0.99231     +0.99988     -0.99982     -0.99847
位移 Δ        +2.977e-05   -3.000e-05   +2.999e-05   +2.995e-05
lr                                                    3.000e-05
```

看第 2 行和第 4 行：梯度從 1.29×10⁻⁶ 到 8.67×10⁻⁵，**差了 67 倍**。
但位移全都是 ± 3×10⁻⁵，**一模一樣**。

因為第一步時 m̂ = g、√v̂ = |g|，相除必定是 ± 1：

$$\frac{\hat{m}_1}{\sqrt{\hat{v}_1}} = \frac{g}{|g|} = \operatorname{sign}(g)$$

> **Adam 讓所有參數走一樣遠，差別只在方向。**
